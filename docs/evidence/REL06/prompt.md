Главная сама направляет гостя на вход и оператора в очередь.

Глобальные Django 400/403/404/500 показывают нейтральный русский HTML по умолчанию, сохраняют соответствующий HTTP-статус, `Cache-Control: no-store`, не выводят URL, ошибки, параметры, сведения о владельце и приватные поля. Если `request.get_preferred_type` предпочитает JSON, сохранить текущий стабильный ключ `status`. Для согласования формата добавить `Vary: Accept`; JSON health и специализированные CSRF/формы/JSON Cat не трогать. Стандартный HTML рендерить без request context, обращения к сессии или каталогу, чтобы работать при падении БД. CSS существующего workspace допустим как необязательное оформление, обработать отсутствующую статическую запись без повторного 500. Один шаблон с доступным заголовком, коротким объяснением и видимым CTA высотой от 44 px, без новых JS, без официальной маркировки. Для обычных GET с невалидными параметрами в расписании, сессии, успеваемости, списках заявок/уведомлений и локальном каталоге использовать общий безопасный 400 вместо plain text. Не менять параметры, методы, JSON endpoint или бизнес-валидацию POST.

Локализовать самодостаточную страницу прокси в `deploy/Caddyfile` через `handle_errors` с `respond <<HTML ... HTML {err.status_code}` и типом HTML. Сохранить исходный код ошибки, no-store, безопасный GET `/` и JSON `{"status":"unavailable"}` при ошибке самого прокси на обоих точных health-путях. Действующие TLS, request limits, logging filters, reverse proxy и CSP не менять. Официальная документация — `https://caddyserver.com/docs/caddyfile/directives/handle_errors` и `https://caddyserver.com/docs/caddyfile/directives/respond`. Независимую проверку Caddy проводит основной на закреплённом образе.
