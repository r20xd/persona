# B07–B09/F05–F06: отчёт исполнителя

Исполнитель: `gpt-6.1-sol`, effort `low`, отдельный вызов без истории родителя.
Реализованы CORE-04, SEC-01 и связанные части TECH-02/03/06, PRD-04;
окончательную приёмку выполняет основной агент.

## Результат

Добавлены `apps/requests/` с первой аддитивной миграцией, селекторами,
транзакционными сервисами, обычными Django-формами и HTML-страницами. Владелец,
начальный статус, actor событий и версии определяются сервером. StudentProfile
блокируется до проверки уникального ключа и часовой квоты; существующий ключ
проверяется раньше квоты. Нормализация пояснения приводит CRLF/CR к LF и убирает
краевые пробелы. Смена статуса блокирует разрешённую строку заявки и проверяет
expected_version. Область оператора проверяется и в селекторе, и в сервисе.

История append-only для штатных save/delete/update/bulk_update; для нового события
принудительно используется INSERT. Это исправление по замечанию основного агента
закрывает перезапись при гонке предварительной проверки существования manual PK.
Регрессионная проверка моделирует отрицательную предварительную проверку и
подтверждает IntegrityError без изменения исходного события. Прямой SQL и намеренный
обход API модельного слоя остаются доверенной серверной границей.

Реализованы список с пагинацией 20 и фильтром статуса, создание, карточка с публичной
историей, отмена, ограниченная очередь и карточка оператора. После успешного POST —
redirect. Конфликт версии — 409 со ссылкой на GET-карточку для получения актуальной
версии; первоначальный вариант ссылки на текущий POST URL исправлен по замечанию
основного агента. Предупреждения поясняют вымышленность данных и отсутствие
настоящего подписанного документа. Профиль теперь содержит рабочие ссылки на заявки.
Предыдущий placeholder-обработчик очереди удалён; route name сохранён.

Новых зависимостей, внешних материалов, сервисов, реальных данных и секретов нет.
CSS написан в проекте, использует существующую палитру. Provision-команда заявок
не добавлялась: browser flow создаёт настоящую заявку обычной формой.

## Фактические проверки

Изолированный PostgreSQL 17.11 из закреплённого digest `deploy/compose.local.yaml`,
одноразовый Docker-контейнер `deanery-requests-qa`, loopback 55432, без host mounts.
В QA используется trust только внутри временного локального контейнера. Контейнер
оставлен основному агенту для независимой проверки; публичной публикации нет.

- `uv sync --locked` с временными cache/python dirs: установлен существующий lock,
  Python 3.13.14 и Django 5.2.19. Без изменения зависимостей/lock.
- `TEST_DB_PORT=55432 PLAYWRIGHT_BROWSERS_PATH=/tmp/deanery-browsers .venv/bin/pytest --browser-channel chromium -q`:
  **111 passed**, одно предупреждение pytest-playwright о будущей совместимости
  session-scoped fixture; приложение не выдаёт ошибок.
- После добавления двух дополнительных регрессий и lock/statement timeouts в
  concurrent worker: `TEST_DB_PORT=55432 .venv/bin/pytest tests/test_requests.py -q`:
  **37 passed**. Все последние изменения касаются проверок; код приложения был
  тем же в полном прогоне.
- `ruff check .`: passed; `git diff --check`: passed.
- `makemigrations --check --dry-run`: No changes detected. При использовании test
  settings вне pytest предупреждает об отсутствующей test_deanery после её удаления
  pytest; в самих pytest миграции успешно применяются к настоящей PostgreSQL-БД.

Проверено: подмена owner/status/actor не меняет серверные значения; same/different
payload-key; quota retry, отменённые в квоте, восстановление спустя час; 25 переходов
матрицы состояний; отсутствие изменения истории при stale version; scope/межгрупповой
и внутригрупповой чужой доступ; фильтры/пагинация/counts; CSRF; XSS как текст;
rollback при ошибке записи события; HTTP 500 без фальшивого успеха при ошибке БД;
устаревшие флаги active/role в переданном actor; insert-only история. Параллельные
проверки используют ThreadPoolExecutor, отдельные Django-соединения, Barrier с
10-секундным timeout, lock_timeout 10s и statement_timeout 15s: duplicate key,
changed payload same key, последние места квоты, два оператора и cancel vs process.

Аддитивная миграция проверена через MigrationExecutor: снятие/возврат requests
0001 сохраняет существующие профиль, занятие и оценку, после возврата создаётся
новая заявка с первым событием.

Chromium проверяет на 360 и 1440 px: настоящий login → создание → refresh → logout
→ operator login → in_progress → ready → student login → сохранённая карточка и
три события → другой студент получает 404. Сервер запускается subprocess Gunicorn,
DEBUG=False, collectstatic; каждая browser fixture имеет отдельную test_browser_*
PostgreSQL-БД, async safety не отключается. Проверены CSS HTTP200, hashed URL,
computed border-radius 18px и отсутствие горизонтального переполнения.

## Ограничения и дальнейшее

B10 notifications ещё не реализован; в сервисах оставлена явная отметка места
будущей записи уведомления внутри той же транзакции. Сейчас статус и история
читаются непосредственно из карточки. Нет файлов, подписанного документа,
публичного размещения или утверждения общей готовности прототипа. Коммит и push
не выполнялись: ожидается независимое ревью основного агента.

Инструменты: Codex, shell/uv/Python/Django, Docker Desktop CLI, PostgreSQL,
pytest/pytest-django, Playwright Chromium, Ruff, Gunicorn/WhiteNoise. Установка
Python/зависимостей/браузера и локальный доступ к Docker/PG выполнены штатным
escalation после отказа sandbox на сеть/loopback; разрешения окружения не менялись.
Ручные пользовательские действия не заявляются — формы в браузере проходил
автоматизированный Playwright. Визуально просмотрен screenshot ready-360.

## Завершение после приёмки

Основной агент независимо принял результат в `review.md`: сообщил полный прогон
**113 passed** за 36.02 s, migration check без изменений, успешные Ruff lint/format
и визуальный просмотр new-360/ready-1440. Это результат родительской проверки,

с `--rm`; последующая команда `docker.exe ps -a --filter
name=^/deanery-requests-qa$ --format '{{.Names}}'` вернула пустой результат,
подтвердив удаление именно временного QA-контейнера. Другие контейнеры/образы
не изменялись. По поручению родителя далее выполняется обычный commit/push
принятого allowlist в `origin/main`; фактический SHA сообщается отдельно.
