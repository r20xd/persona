# B07–B09/F05–F06 — независимая приёмка

Статус: accepted для реальных заявок и ограниченной обработки оператором. Основной агент gpt-6.1-sol/high, исполнитель gpt-6.1-sol/low. Уведомления B10 остаются следующим блоком.

## Что проверено

Родитель прочитал модели/ограничения, создание и переходы в transaction.atomic, scope-selectors, формы/маршруты/ошибки, шаблоны и риск-тесты. Владелец задаётся сессией; роли/активность перечитываются из БД. Выборка ограничивается владельцем или OperatorScope до поиска UUID. Квота сериализуется блокировкой профиля, проверка существующего ключа идёт раньше лимита. Версия и row lock защищают переходы. RequestEvent записывается вместе с заявкой/статусом, не отдельной ненадёжной операцией.

Независимая команда: `DB_PORT=55432 TEST_DB_PORT=55432 PLAYWRIGHT_BROWSERS_PATH=/tmp/deanery-browsers .venv/bin/pytest --browser-channel chromium`. Результат: **113 passed**, 36.02 секунды, PostgreSQL17 + Chromium. Migration check: No changes detected. Ruff lint/format: успешно,120файлов. Whitespace check: успешно. Один upstream warning pytest-playwright касается будущего pytest10; текущий lock использует pytest9.

Подтверждены: scope группы и владельца, одна/разные группы, оператор без области доступа, прямые GET/POST к чужим UUID, пагинация/counts/фильтры, CSRF, XSS как текст, подстановка owner/status, нормализация повторного payload, такой же key у другого студента,409 на другой payload,30новых/час включая отменённые, retry при исчерпанной квоте, две одновременные отправки/разный payload,25переходов матрицы, терминальные состояния, причина отказа, conflict version, два оператора и отмена против обработки, откат при ошибке события, неизменяемость обычных model API и INSERT-гонка, stale actor, отсутствие ложного успеха при DB-сбое. Тест миграции сохраняет ранее созданные профили/занятия/результаты.

## Исправления по ревью

- Новые RequestEvent принудительно используют INSERT: race после exists-проверки не может перезаписать историю.
- Recovery после POST-конфликта ведёт GET-ссылкой на карточку и свежую expected_version, а не на POST-only /transition/ или /cancel/.
- Добавлено явное подтверждение разделения owner/submission_key между студентами.
- Шаблоны разбиты на читаемые строки.

Родитель просмотрел new-360.png и ready-1440.png: форма/статус/история читаются, комментарии и смысл демонстрационной справки понятны. Реальный Chromium round trip360/1440 выполняет вход студента, создание, обработку оператором, возврат студента к сохранённому статусу, проверяет CSS200/computed styles и отсутствие overflow. Screenshot не заменяет проверку серверных прав: она отдельно прошла в PostgreSQL.

## Границы

Создаётся конкурсная демонстрационная справка без файла и официальной подписи. Нет вложений, редактирования owner/истории или административного доступа жюри. Notification пока не создаётся: B10 добавит его в ту же транзакцию по request/version. Прямой доверенный SQL остаётся вне обычного model API. Публикация, сети РФ, настоящий телефон, нагрузка и эксплуатационные backup ещё не проверены. Удалённый CI не подтверждён.

Принятый этап фиксируется с атрибуция команды. После QA убрать только собственный временный контейнер; следующий блок — уведомления/объявления/дедлайны и сводная главная.
