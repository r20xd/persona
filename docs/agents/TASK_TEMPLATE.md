При пересечении владельцев остановить изменение затронутого файла и сообщить родителю.

## Формат отчёта

Верни короткий результат и сохрани его в разрешённом `implementation.md`:

- Что сделано и какие требования покрыто.
- Изменённые файлы и назначение каждого.
- Выполненные команды/сценарии, фактический результат и код возврата, если доступен.
- Оставшиеся ограничения, блокировки и непроверенные критерии.
- Новые решения, требующие ревью; ссылки на реальные артефакты без секретов.

Исполнитель не принимает собственную задачу: финальный статус выдаёт родитель после независимого ревью.

- **Статус push:** `<pending | committed / push pending | pushed>`.
- **SHA локальной и удалённой веток после push:** `<два фактических SHA либо причина недоступности>`.

Следуй разделу версионирования `WORKFLOW.md`: один владелец index, проверка уже staged изменений, `git add --` только по allowlist, просмотр полного staged diff и результатов тестов до commit. Не использовать `git add .`, force push, пустые коммиты, сброс чужих изменений или amend опубликованной истории; не включать секреты. При ошибке push сохранить commit, зафиксировать pending и не создавать повторный commit без новых изменений. Sandbox и защищённый `.git` не обходить; при необходимости использовать штатную escalation и отдельно записать внешнюю блокировку. Отчёт после commit может остаться для следующего согласованного commit без переписывания истории.
