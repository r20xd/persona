# PERS01 — «Моя персона» в профиле

Исполнитель gpt-6.1-sol / low, один writer. Требования PRD-01/02/03/04/05, SEC-01, TECH-03/06, DATA-01; PLAN §§2/4.1/5. Пользователь явно поручил новую функцию личной карточки; контракт ARCHITECTURE.md §25 — решение родителя.

Прочитать TASK.md, AGENTS.md, ARCHITECTURE.md §§5–7/10/25, PLAN §§4.1/5, docs/agents/WORKFLOW.md и existing accounts/services/selectors/forms + tests/ui_qa.py.

Цель: «Моя персона» внутри /profile/: сильные стороны, интересы, чему хочу научиться, вне учёбы, одна цель на семестр и отметки прогресса. Персональная карточка с выбранными тегами, красивой короткой фразой из ответов, кнопкой «Редактировать»; empty invitation «Расскажите о себе». Всё приватно и сохраняется после logout/login, mobile360. Не добавлять обратно удалённые shortcuts профиля или student label header. Никаких psychological typing/AI inference/public sharing.

Контракт данных: новая StudentPersona OneToOne student StudentProfile(PROTECT), JSONField(default=list) strengths/interests/skills/activities — только массивы фиксированных кодов из options в отдельном persona.py/choices module. Strengths включают выступать/анализировать/придумывать/организовывать; интересы языки/дипломатия/технологии/творчество (можно ещё4нейтральных); skills выступать/переговоры/исследования и до3прочих; activities дебаты/фото/волейбол и до5прочих. Максимум8выборов/поле, form+service validation, никаких произвольных JSON от клиента. goal CharField160 blank, progress PositiveSmallInteger default0, form choices0/25/50/75/100; DB Check0<=progress<=100. Без цели progress0 (валидация или нормализация). Обычная timestamp updated_at. Никаких настоящих сведений в seed: persona не seed-ить, показать empty.

HTTP: GET /profile/ read-only, никаких новых writes; GET/POST /profile/persona/ name persona-edit own_profile(request.user), CSRF/no-store/login/role; POST service save_persona(actor, cleaned values) заново проверяет own_profile, нет student_id/owner из формы. PRG to profile valid, invalid200 с field errors и input сохранён. POST /profile/ остаётся405. Other methods405. Другой студент не видит чужое и не может изменить через id/payload. Не принимать next/return URL от клиента. XSS autoescape, без safe/innerHTML. Короткая итоговая фраза только из выбранных пунктов (до3частей), не присваивать личности тип.

Разрешённые файлы: apps/accounts/{models,forms,views,urls,services,selectors}.py; новый apps/accounts/persona.py (options/helper); одна новая migration после existing accounts migrations; apps/accounts/templates/accounts/profile.html и новый persona_edit.html (можно persona_card.html); новый static/css/persona.css; tests/test_persona.py и tests/test_persona_browser.py; docs/evidence/PERS01/implementation.md и screenshots PERS01. Существующие auth functions не ломать/не рефакторить; серверный login, fingerprint, cookies и модели профиля сохраняются. Если нужен иной файл — сообщи. Не менять deps/config/shared CSS/прочие apps или historical evidence. Не делегировать, не commit/push до accepted. Не трогать user .env/DB. .DS_Store/persona.jpeg/palitra.jpeg не включать в commit.

UI: palette persōna, tasteful card с крупным заголовком, тегами выбранных ответов и отдельной целью/progress; checkbox chips с реальными accessible labels и видимым keyboard focus. Персональная карточка и editor выглядят как часть профиля. На edit компактные fieldsets с4группами и goal/progress. Не auto-submit persona POST — явная «Сохранить персону», «Отмена» link profile. Без JS полностью работает. Подсказка «Видно только вам» и не просить чувствительные данные. Поля пустые разрешены, нет обязательного психологического опроса.
