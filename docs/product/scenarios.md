# P02 — пользовательские сценарии

Это критерии будущей реализации, а не отчёт о выполненных тестах. Все даты показываются по Москве. Основные состояния доступны обычными HTML-страницами и формами.

| ID / требование | Начало и действие | Ожидаемый результат | Ошибка или крайний случай |
| --- | --- | --- | --- |
| SC01 / CORE-01 | Гость открывает кабинет и вводит выданные логин/пароль | Студент попадает на главную, оператор — в очередь заявок | Неверный вход не раскрывает существование аккаунта; локальный next; блокировка с понятным cooldown |
| SC02 / CORE-01 | Студент открывает профиль из шапки | ФИО, факультет, направление, курс и группа только его аккаунта | Нет страницы поиска чужих профилей; повреждённый профиль даёт понятную ошибку |
| SC03 / CORE-02 | Главная → ближайшее занятие → расписание | Сегодня/неделя, время, аудитория, преподаватель | Выходной/пустая неделя честно пусты; предложен следующий день/неделя |
| SC04 / CORE-02 | Студент открывает отметку переноса | Видит старое и новое время/место и причину | Отмена сохраняет карточку; перенос на другую неделю не создаёт активный дубль |
| SC05 / CORE-03 | Студент открывает «Учёбу» и семестр | Видит опубликованные оценки/зачёты и понятный итог | Отсутствующая оценка не равна нулю/провалу; будущая публикация не входит в итог |
| SC06 / CORE-03 | Студент открывает вкладку «Сессия» | Видит экзамены/зачёты, даты, место и доступные результаты | Нет событий — понятное пустое состояние, без вымышленной даты |
| SC07 / CORE-04 | Главная → «Заказать справку» → назначение/пояснение → отправка | Сохранённая заявка со статусом «Отправлена» и номером | Двойное нажатие/повтор после обрыва сети создаёт одну заявку; невалидные поля сохраняют введённый текст |
| SC08 / CORE-04 | Студент повторно входит и открывает заявку | Сохранились статус, история и ответ оператора | Чужой UUID даёт 404; owner из POST не используется |
| SC09 / CORE-04 | Оператор открывает очередь, берёт заявку, завершает или отклоняет | Статус и событие изменены атомарно, причина отказа видна владельцу | Вне scope — отказ; устаревшая версия → 409 и предложение обновить карточку |
| SC10 / CORE-05 | Студент открывает уведомления и отмечает запись прочитанной | Отметка меняется только у него; ссылка ведёт к актуальному разрешённому объекту | Чужой ID недоступен; удалённая/недоступная цель не раскрывает сведения |
| SC11 / CORE-05 | Приближается или переносится срок | На главной актуальная дата, в ленте одно напоминание на событие/ревизию | Повтор timer не дублирует записи; уже опубликованный результат подавляет соответствующее напоминание |
| SC12 / SEC-01 | Выйти из A, войти в B, нажать Back, открыть вторую вкладку | Нет доступных данных A в страницах и действиях B | Истёкшая сессия ведёт на вход; private DOM не сохраняется HTMX в localStorage |

## Сквозная демонстрация

Студент A: вход → сегодня/неделя и перенос → оценки/сессия → создание справки → выход. Оператор: вход → обработка этой заявки → выход. Студент A: повторный вход → статус/ответ/уведомление. Студент B: другой профиль и учебные данные, недоступность заявки A. Повтор основного пути на телефоне 360 px.

Проверки отсутствия чужих данных выполняются также прямыми серверными запросами, включая студента той же группы. Визуальная демонстрация не заменяет security-тесты.
