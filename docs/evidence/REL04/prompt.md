# REL04 · Действия в пустом расписании

Выполнить UX-часть REV-05 из `docs/evidence/REV01/audit-and-plan.md`. Связанные требования CORE-02, PRD-02, PRD-04, TECH-06. Прочитать TASK.md, AGENTS.md, ARCHITECTURE.md §9 и §11, а перед изменением интерфейса прочитать текущий `/Users/local-user/.codex/plugins/cache/taste-skill/taste-skill/2.5.1/skills/taste-skill/SKILL.md`. Согласованная палитра, сетка, вкладки и формы остаются прежними.

Когда текущий таймлайн пуст, дать в карточке прямое действие. Для дневного режима — «Открыть неделю» с тем же выбранным днём. Для обоих режимов — «Ближайшее занятие» при наличии собственного будущего занятия начиная со следующего периода. Найти его ограниченным запросом в selectors на основе `own_enrollments`, исключить отмены, не делать дополнительный запрос для заполненной страницы. Ссылка открывает дневной режим нужной даты по Москве. Без следующего занятия дружелюбно предложить выбрать дату. Статический HTML работает без JS. Использовать существующие классы и небольшой scoped CSS только если нужно. Сохранить обычное текстовое состояние и защиту фильтров.

Разрешены `apps/schedule/selectors.py`, `apps/schedule/views.py`, `apps/schedule/templates/schedule/schedule.html`, `static/css/schedule.css`, `tests/test_schedule.py`, `docs/evidence/REL04/implementation.md`. Основной агент выполняет независимое браузерное ревью на 360 и 1440 и сохраняет снимки. Смежный REL03 меняет только команды демоданных и свой тест. Серверный тест должен подтвердить ссылки на верный период и своё ближайшее занятие, исключение отменённого и чужого, пустую неделю без будущего. Проверка стиля и ограничений ширины обязательна для изменённого интерфейса. Не читать рабочую .env, не использовать рабочую БД, не коммитить, не запускать субагентов.
