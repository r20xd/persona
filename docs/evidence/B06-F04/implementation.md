# B06/F04: успеваемость и сессия

Исполнитель: `gpt-6.1-sol / low`, назначение явным вызовом родителя.
Требования: CORE-03, SEC-01, PRD-04/05, TECH-03/06, DATA-01, BRAND-01.

Реализовано приложение `apps.grades`: Assessment, GradeResult, ExamEvent и
начальная миграция. Внутренние транзакционные сервисы блокируют курс и записи,
проверяют full_clean, соответствие enrollment/assessment, формы контроля,
диапазон баллов и aware-время. DB constraints проверяют допустимые значения,
взаимоисключение баллов/исхода, уникальность итоговой аттестации, пары результата
и попытки события. Межтабличные проверки находятся в clean/сервисах; прямые bulk
ORM-записи не являются поддерживаемым способом изменения данных.

GET `/grades/`, `/session/` сначала ограничены собственными Enrollment. Список
семестров тоже персональный. Все будущие/неопубликованные результаты исключаются
до построения строк и итогов. Отсутствие оценки означает ожидание, а ноль текущей
работы отображается как 0 / максимум. Итог считается по дисциплинам, без среднего
балла разных шкал. Экзамен отображает 5/4/3/2 и словесный исход; зачёт — словесный
исход. Сессия содержит дату, попытку, преподавателя, аудиторию, отменённые события;
ссылка в успеваемость сохраняет семестр. Гости перенаправляются на вход, оператору
отказано. Произвольные/множественные фильтры отклоняются. HTTP редактирования нет.

Команда `provision_grades_demo` требует существующие два профиля и учебные данные,
добавляет вымышленные баллы (включая 0), опубликованные/будущие и отсутствующие
итоги, события экзаменов/зачётов; повторение сохраняет результаты и пароли.
Профиль содержит работающие ссылки на новые страницы. Использованы существующие
локальные CSS, шрифты, символ бренда; новых зависимостей и сторонних материалов нет.
