# V2 — проверка цельного кабинета пользователем

Кандидат `архивная-версия` прошёл повторную локальную репетицию. Согласование V2 остаётся за пользователем. [Проверки и снимки кандидата](../REL09/review.md)

Если кабинет уже открыт на этом компьютере, начните с первого шага сценария. [Открыть страницу входа](http://127.0.0.1:8000/login/)

## Запуск

Из корня репозитория выполните раздел «Локальный запуск» README.md: установите зависимости, заполните приватный `.env`, загрузите его в окружение и запустите PostgreSQL через Compose. Пароли базы и SECRET_KEY не публикуйте. Не удаляйте volume с нужными данными.

После подготовки БД:

```bash
uv run python manage.py migrate
uv run python manage.py seed_demo
uv run python manage.py prepare_demo_window
uv run python manage.py collectstatic --clear --noinput
DJANGO_SETTINGS_MODULE=config.settings.local uv run gunicorn config.wsgi:application --bind 127.0.0.1:8000 --threads 4
```

При первом запуске `seed_demo` скрыто запросит пароли трёх демонстрационных аккаунтов. Используйте отдельные вымышленные тестовые доступы. При повторе команда сохраняет существующие пароли и действия. Сервер работает в этом терминале до Ctrl+C; публичный доступ не открывается. На этапе Q04 локальный запуск уточнён до четырёх потоков Gunicorn, как в проверенном браузерном QA-контуре; production-настройка остаётся отдельным этапом.

Адрес: http://127.0.0.1:8000/login/. Логины: `student.one`, `student.two`, `operator.demo`; пароли — заданные при первоначальном создании. Внешний вид телефона можно посмотреть в инструментах браузера при ширине 360 px. Проверка на физическом телефоне остаётся отдельным шагом.

## Что проверить

1. Войдите как `student.one`. На главной посмотрите, понятно ли, что предстоит по учёбе и что требует внимания. Откройте профиль, расписание дня и недели, успеваемость и сессию. На телефоне ссылка на успеваемость называется «Учёба». Если день пуст, откройте «Ближайшее занятие». В блоке «Требует внимания» или «Изменения на неделю» откройте перенос и проверьте новую дату и аудиторию.
2. Создайте справку из раздела заявок, откройте её карточку. Сохраните адрес. Выйдите и войдите повторно: заявка должна остаться.
3. В отдельном приватном окне войдите как `operator.demo`. Найдите созданную заявку, переведите в работу и затем в готовые. В студенческом окне обновите карточку и уведомления: должны появиться новый статус и история.
4. Войдите как `student.two`. Сравните профиль, время занятий той же недели и результаты. Адрес заявки первого студента должен вернуть отсутствие доступа (404), а сама заявка не должна появиться в списке.
5. Повторите отправку заявки при ширине 360 px. Проверьте читаемость текста, навигацию, поля и кнопки, отсутствие перекрытия нижней панелью.

Все сведения вымышлены, документы демонстрационные. Посетители одного общего демоаккаунта видят действия друг друга; изоляция проверяется между разными аккаунтами.

## Решение пользователя

Нужно подтвердить удобство полного пути и готовность перейти к подготовке первого публичного релиза либо перечислить необходимые изменения. Палитра уже одобрена на V1, название остаётся рабочим. Хостинг, домен и расходы согласуются отдельно при выборе размещения. Автоматические проверки и это согласование не заменяют проверку опубликованного сайта из России.
