## Законченный результат

1. Воспроизводимая локальная репетиция нагрузки на собственной изолированной БД и web, без приёма произвольного URL/production DSN.20 отдельных аутентифицированных сессий, созданных настоящим login с CSRF (можно повторно использовать два демоаккаунта, но cookie jars независимы). Реальный DEBUG=False Gunicorn/WhiteNoise, начально2 workers/4threads, CONN_MAX_AGE/Argon2/security не отключать. Read workload по основным страницам: прогрев отдельно, затем несколько раундов с20 одновременно активными readers; сами workers синхронизированы barrier/ограниченным ThreadPool, не последовательный loop с цифрой20 в отчёте.
2. Измерять read p50/p95/max и counts по маршруту/overall, количество non200/5xx/ошибок/неожиданного redirect; чтение не должно silently превратиться в login200. Проверять ожидаемые признаки собственного аккаунта/страницы и отсутствие чужого личного содержимого хотя бы контрольными запросами до/после. Login измерять отдельно (реальный Argon2), подготовку20 сессий выполнять последовательно или с безопасной малой конкурентностью; не нагружать20 одновременными Argon2 без оценки памяти. Отчёт не содержит cookies/credentials/HTML/DSN/ФИО, только технические агрегаты и фиктивный dataset size.
3. Начальный внутренний ориентир read p95<1s, без5xx,20сессий из ARCHITECTURE — не условие конкурса и не заранее обещанная вместимость VPS. Записать actual CPU/memory/runtime/Gunicorn/PG/dataset/прогрев/раунды/время/метод percentile. Если ориентир не достигнут, показать факты/узкое место, не ослаблять assertions/хеширование и не выдавать localhost измерения за production гарантию. Запуск с ошибкой/утечкой/неподтверждённым dataset должен ненулево завершаться; отличие performance target от функционального failure описать явно.
4. Query audit: реальные server-rendered GET для dashboard/schedule/grades/session/requests/notifications и operator queue, начальный и расширенный собственный dataset, materialize templates. Выявить N+1/неограниченную выдачу/дорогие fixed queries; использовать CaptureQueriesContext/execute_wrapper без DEBUG=True. Не сохранять SQL с данными/параметрами. Проверки по риску, не зеркальные asserts каждого запроса. Если нужен app fix — сначала сообщить профиль и минимальные файлы/контракт родителю; auth/ownership/раскрытие drafts не менять молча. Индексы/миграции только после отдельного решения.
5. Dependency audit с актуальной базой advisories: pip-audit либо равноценный официальный инструмент, отдельно runtime и dev closure locked окружения. Audit tool можно запускать uvx/отдельным /tmp env без изменения app lock. Никакого чтения user env/отправки секретов: передаются только публичные package/version, отчёт содержит дату/source/версию инструмента/scope/findings/статус запроса. Если сеть/база недоступна — не называть результат «уязвимостей нет». На найденные CVE первым делом report родителю, проверка официального advisory и patch plan; dependencies/lock пока не менять. Root параллельно занимается лицензиями и CI metadata.
