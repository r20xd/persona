# Q02 — целостность и конкурентность: инвентаризация

Итоговая сверка services и существующих проверок выполнена от архивная-версия. Узкий прогон исполнителя — docs/evidence/Q01-Q02/implementation.md; независимый полный прогон фиксирует основной агент. Это карта существующих гарантий и пробелов, а не обещание поведения при любой аварии.

| Инвариант | Реализация | Проверка |
| --- | --- | --- |
| Неизменённый повтор заявки возвращает прежнюю запись, включая повтор после достигнутой квоты | profile rowlock, unique(student,submission_key), проверка ключа до квоты | `test_creation_idempotency_quota_and_forgery`, `test_parallel_idempotency_and_quota`; `tests/test_integrity_audit.py::test_parallel_submit_has_only_owner_initial_effects` подтверждает одно initial event/notification и отсутствие новых effects при retry |
| Изменение payload с прежним ключом409; CRLF/CR/пробелы канонизируются | normalized_payload и сравнение внутри транзакции | `test_creation_idempotency_quota_and_forgery`, `test_parallel_changed_payload_conflicts` |
| Owner/status/version нельзя выбрать полями формы создания | actor из серверной сессии, явные cleaned fields | `test_creation_idempotency_quota_and_forgery` |
| Переход статуса допустим только по таблице, с правильной ролью и версией | request rowlock, expected_version, terminal states, scope reload | `test_complete_transition_matrix`, `test_transition_table_versions_and_public_history` |
| Два оператора / отмена против обработки не создают два победивших перехода одной версии | PostgreSQL SELECT FOR UPDATE, версия после блокировки | `test_parallel_transitions_and_cancel`; дополнительно `tests/test_integrity_audit.py::test_winning_transition_has_one_history_and_notification[operator/cancel]`: разные scoped операторы / отмена против обработки, отдельные DB-соединения, одна победившая история и notification на версию только владельцу |
| Заявка, event и notification появляются атомарно | единая transaction.atomic; исключение notification откатывает источник | `test_atomic_event_failure_rolls_back`, `test_atomic_source_events_and_dedupe`; `tests/test_integrity_audit.py::test_notification_failure_preserves_existing_history_then_retry` сохраняет полные прежние события/уведомления/read_at при injected notify failure после двух версий, затем retry создаёт ровно третью версию |
| История заявки не перезаписывается обычным ORM API | append-only model/queryset, forced INSERT, уникальная версия | `test_model_constraints_immutability_and_stale_actor`, `test_insert_only_even_when_existence_check_races` |
| Две правки расписания одной версии не обе проходят | lesson rowlock и expected_version | `test_parallel_changes_lock_and_conflict`, `test_moves_cancel_snapshots_and_rollback` |
| Напоминания/прочтение повторяемы, учитывают перенос/отмену и пропущенный timer | ReminderRun lock, revision/phase/recipient unique dedupe, личные timestamps | `test_deadline_revision_reminders_suppression_and_missed_run`, `test_parallel_reminders_and_reads` |
| Два seed не дублируют fixtures, повтор не сбрасывает действия | advisory transaction lock, стабильные коды/UUID, profile lock для request fixture | `test_concurrent_seed_serializes`, `test_seed_preserves_actions_and_identifiers`, `test_seed_keeps_preexisting_fixture_request` |

Тесты перечислены без префикса файла: request-инварианты — tests/test_requests.py; notification — tests/test_notifications.py; schedule — tests/test_schedule.py; seed — tests/test_dashboard_demo.py. Конкурентность проверяется PostgreSQL, а не SQLite или последовательными браузерными кликами.

Отказ БД не даёт ложного сообщения об успехе (`test_database_failure_never_shows_success`). Q04 добавил контролируемую потерю ответа после реального commit: Playwright route.fetch отправляет настоящий POST, route.abort скрывает ответ от браузера, сохранённая карточка находится в собственном списке. Повтор исходного тела с CSRF/submission_key возвращает тот же detail UUID, счётчик увеличился ровно на1. Это подтверждено новым browser regression на Chromium/Firefox/WebKit и независимым прогоном основного агента; отдельный abort до отправки не меняет БД.

Это инъекция сбоя доставки HTTP-ответа, не выключение сети/диска во время самой транзакции и не production disaster recovery. Q05 подтверждает локальный restart/dump/restore. Q02 сверяет перечисленные инварианты текущих сервисов; существующие ограничения остальных Q/D сохраняются. Новые races используют прежний race helper с barrier timeout10s, lock_timeout10s и statement_timeout15s; неожиданные исключения потоков не скрываются. Проверка не обещает сериализацию конкурентного административного отзыва role/scope: такого UI/протокола в baseline нет.
