# Ключевые сценарии приёмки

Это критерии, а не уже полученные результаты.

| Ситуация | Результат |
| --- | --- |
| Student A создаёт справку | owner из сессии, submitted/version1, одна запись и одно начальное событие |
| Повтор A/key, тот же payload после нормализации | Та же заявка, без события и нового расхода квоты |
| Повтор A/key с другим payload |409, старая заявка не меняется |
| B использует тот же key | Не получает заявку A; scope owner/key самостоятельный |
|30новых за час, включая отменённые |31-я429; конкурентные отправки не обходят лимит |
| Повтор существующей при исчерпанной квоте | Возвращает имеющуюся, не429 |
| Чужая заявка/переход из URL |404, нет чужого имени/содержимого/количества |
| Оператор без scope | Не читает и не меняет заявку; роли проверяются и в сервисе |
| submitted → cancelled | Только владелец, только актуальная версия |
| submitted → in_progress → ready/rejected | Только разрешённый оператор; отказ с причиной |
| Повтор старой версии / два оператора / отмена против обработки | Одна допустимая запись, конфликт409; история цела |
| Исключение при записи события | Вся операция откатывается, нет состояния без события |
| CSRF/XSS/status-owner forgery | Не меняет чужие данные; комментарий показывается текстом |
| Перезагрузка и новый вход | Заявка/история не исчезают |

Статус ready — демонстрационная готовность, без официальной справки/подписи. Уведомления B10 — следующий этап: сейчас атомарны заявка и событие, позднее Notification будет добавлен в ту же транзакцию, а не ненадёжным сигналом после commit. Не считать CORE-05 завершённым этим блоком.
