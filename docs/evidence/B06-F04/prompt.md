# B06/F04 — успеваемость и сессия

Пользователь: «продолжай». По STATE следующий блок — реальные результаты обучения и экзамены/зачёты. V1 одобрена, палитра сохраняется, название рабочее.

Исполнитель grades: gpt-6.1-sol/low, отдельный контекст fork_turns=none; основной агент gpt-6.1-sol/high. Требуется создать Assessment/GradeResult/ExamEvent, их миграции, внутренние валидирующие сервисы и собственные выборки через Enrollment, GET /grades/ и /session/ с выбором своего семестра, пустыми состояниями, понятным итогом и мобильными экранами.

Техническое уточнение родителя: не более одной итоговой аттестации на CourseOffering, произвольное число текущих работ. Это позволяет считать завершённые/ожидающие/неуспешные дисциплины без неоднозначного усреднения. Экзаменационные попытки остаются отдельными ExamEvent. Совместимые типы: coursework → points/max; exam → excellent/good/satisfactory/unsatisfactory; credit → passed/failed. Отсутствие результата не является нулём или задолженностью. Будущие/неопубликованные результаты исключаются из HTML и всех сводок.

Область исполнителя: apps/grades/, config регистрации/маршрутов, реальная навигация профиля, grades.css, tests, README и implementation/PNG в этом каталоге. Родитель владеет prompt/review, STATE/PLAN/ARCH/AGENTS. Без новых зависимостей, публичных HTTP-функций выставления оценок, recursive agents и commit до приёмки. Обязательное соавторство: команда persōna <noreply@persona.example>.

Приёмка: PostgreSQL17, ограничения и cross-offering проверки, изоляция своей/чужой группы и студента той же группы, guest/operator, фильтры семестров, нулевой балл и границы шкал, итоговые counts, скрытая будущая публикация, события/попытки сессии, повторяемое дополнение вымышленных данных без сброса аккаунтов/оценок. Браузер360/1440, CSS200/computed style/no overflow, полный регрессионный suite и миграция с сохранением ранее созданных профилей/занятий.

Используется только собственный временный контейнер через native Windows Docker CLI, loopback55432, без host mounts. QA-данные вымышлены, trust допустим только у этого disposable service. После handoff родителю и независимых проверок остановить/удалить свой контейнер; не трогать чужие ресурсы и системные права. Пароли не выводить/не передавать argv; QA server после проверки остановить.
