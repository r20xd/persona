# ANN01 — реализация

Требования: CORE-05, PRD-04, PRD-05, SEC-01, TECH-03.

Исполнитель: Codex / gpt-6.1-sol, Python/Django, ruff, pytest. Прочитаны TASK, AGENTS, архитектурные контракты 6/7/9, актуальный Taste Skill 2.5.1. Дизайн расширяет существующий кабинет: прежняя палитра, кнопки, поля и одна колонка формы на телефоне; без новых изображений, шрифтов и зависимостей.

Добавлен GET/POST `/operator/announcements/new/`. Оператор переходит из блока «Объявления деканата», выбирает одну закреплённую группу по коду и публикует заголовок и текст. Ошибки видны рядом с полями, hidden UUID не выводится обычным полем. Нет закреплённых групп — объяснение без кнопки отправки. PRG ведёт к карточке объявления с `#announcement-ID`; оператор видит код группы.

Запись проходит атомарный сервис: актуальные активная роль и OperatorScope проверяются на сервере; строка пользователя и выбранный scope блокируются до commit. Стабильный UUID5 scoped actor/submission key помещается в уникальный Announcement.code. Одновременные одинаковые отправки сериализуются; одинаковая форма возвращает исходную запись, изменённое содержимое выдаёт ошибку формы и ссылку на новую. Исходные данные не переписываются. Общие и факультетские объявления через эту форму не создаются. Чтение оператора расширено только группами из OperatorScope; студенческая аудитория и read отметки сохраняются. CSRF middleware и no-store включены.

ИИ-исправления в процессе: после независимого замечания основного убран повторный id у контейнера ошибок Django; повтор UUID с другим содержимым изменён с молчаливого возврата исходной записи на доступную ошибку с дальнейшим действием.

Проверки: ruff check/format; pytest notifications + access_matrix, 163 passed после исправлений сервиса/шаблона. Тесты подтверждают роли, CSRF, пустую область, недопустимую группу, повтор/конкурентность, серверную проверку деактивации/снятия scope, две группы, escaping, сохранение прежней аудитории и read-поведения. Подключение в sandbox к loopback изначально отклонено ОС; штатный require_escalated дал выполнить проверки на отдельной disposable QA PostgreSQL. Рабочая БД не менялась.

Добавлен браузерный тест 360/1440: пустая отправка → заполнение → публикация/якорь → reload без дубля → student.one видит → student.two не видит. Запуск браузера, collectstatic и визуальная независимая приёмка переданы основному агенту; в этом отчёте они не объявляются выполненными. Taste gate здесь не запускался: используются существующие серверные страницы и ограниченная область файлов, визуальную проверку выполняет основной. Никаких commit/push/deploy исполнитель не делал.
