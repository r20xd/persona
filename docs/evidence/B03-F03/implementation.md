# B03 / B04 / B05 / F03 — результат исполнителя

Дата: 2026-11-04. Исполнитель: gpt-6.1-sol, low; задача получена от основного
агента, без дочерних агентов. Требования: CORE-02, PRD-04/05, SEC-01,
DATA-01, TECH-03/06; B05 до интеграции уведомлений B10.

## Реализовано

- Учебные справочники Term/Subject/Teacher/Room, CourseOffering и персональный
  Enrollment. Уникальные пары/тройки, контроль exam/credit, даты семестра;
  enroll проверяет совпадение группы и допускает безопасный повтор.
- Lesson с UUID, московскими границами семестра и aware-временем; DB checks
  для времени, статуса и положительной версии. LessonChange хранит версию,
  old/new время, статус, ссылки и текстовые снимки комнаты/преподавателя.
- Внутренние create_lesson/change_lesson: atomic, select_for_update,
  expected_version и StaleLessonVersion. Ошибка записи истории откатывает
  изменение занятия. Публичных HTTP-команд записи нет, оператор заявок
  расписание не читает и не редактирует.
- `/schedule/?date=YYYY-MM-DD&view=day|week`: московский день, понедельник,
  исключающая верхняя граница, стабильный порядок, ссылки назад/вперёд/сегодня,
  date picker, состояния пустого периода. Неверные/повторные/неизвестные query
  параметры и переполнение дат возвращают 400. Ответы no-store.
- Перенос сохраняет UUID; на старом интервале видна историческая отметка,
  ссылка ведёт на конечную текущую дату. Внутри одной недели видны и отметка,
  и единственная текущая карточка. Общая лента сортируется по времени карточки
  или старому времени исторической отметки; browser проверяет порядок2→4→6
  ноября. Отмена оставляет карточку и историю.
- Настоящий профиль содержит ссылку на расписание; доступны обратная ссылка,
  профиль и CSRF-защищённый POST-выход. UI использует текущую палитру V1,
  локальную статику, подпись конкурсного концепта и вымышленные данные.
- `provision_study_demo` требует два уже созданных профиля, не меняет доступы,
  создаёт стабильный якорь и шесть недель занятий. Повтор с другой датой не
  сдвигает существующие данные и не сбрасывает служебные изменения. Общий
  вымышленный преподаватель не имеет пересечений демозанятий.

## Проверки

Среда: временный PostgreSQL17.11, pinned image из deploy/compose.local.yaml,
контейнер `deanery-schedule-20261104`, loopback55432, без host mounts/volume.
Trust-auth использован только для одноразовой локальной QA-БД. Для запуска
native Docker Desktop CLI и loopback QA потребовался require_escalated.

- Ruff check и format --check прошли; Django check — без ошибок;
  makemigrations --check --dry-run — No changes detected.
- Полный pytest с PostgreSQL17.11 и Chromium: **65 passed, 1 warning**
  за15.30s. Warning — upstream PytestRemovedIn10Warning из pytest-playwright;
  приложение ошибок не выдало. Targeted schedule+browser —19passed. Команда:
  `DB_PORT=55432 TEST_DB_PORT=55432 PLAYWRIGHT_BROWSERS_PATH=/tmp/deanery-browsers .venv/bin/pytest --browser-channel chromium -q`.
- Ограничения и матрица доступа: гость, владелец, студент той же группы без
  Enrollment, другая группа, оператор; подстановка ID/фильтров, отсутствие
  чужой истории, запрет POST.
- Границы: московская полночь из UTC, понедельник/воскресенье, активная UTC-зона
  не меняет московскую валидацию Term; naive-время отклоняется.
- Переносы между/внутри недель, повторные переносы, отмена, смена помещения
  и преподавателя, снимки после переименования справочника, stale version,
  rollback; два worker с Barrier и разными DB-соединениями дают один успех,
  один конфликт и одну запись истории. Проверена уникальность версии.
- Миграционный smoke: на схеме accounts0002 созданы аккаунты, затем применены
  последние миграции; IDs, поля профилей и password hashes сохранились;
  provision_study_demo после обновления прошёл. Служебные значения не выведены.
- Настоящий вход и day/week на360/1440 проверены Chromium через Gunicorn и
  WhiteNoise при DEBUG=False. collectstatic выполнен; hashed CSS200,
  computed border-radius18px, отсутствие горизонтального переполнения,
  переход с отметки на актуальное занятие и выход проверены. Скриншоты:
  `schedule-day-360.png`, `schedule-week-360.png`,
  `schedule-day-1440.png`, `schedule-week-1440.png`.

Первый полный прогон выявил несовместимость ORM-setup браузерной фикстуры с
активным event loop Playwright. Исправлено отдельной `test_browser_*` БД и
subprocess-командами provisioning; async safety Django не отключалась.
Предварительные тесты также обнаружили ошибочный слишком длинный invalid
контроль и истёкшую сессию под mock времени — исправлены сами тесты.
После замечаний review добавлены текстовые снимки, явная Москва в Term,
отметка переноса внутри недели и принудительный INSERT новой записи истории.

## Границы

Уведомления B10 и CORE-05 ещё не реализованы. Это локальная проверка, а не
публикация и не приёмка всего конкурсного прототипа. Реальный телефон,
доступность из сетей России и работа до итогов здесь не проверялись.
Неизменяемость истории обеспечивается штатными model save/delete и сервисным
контрактом; доверенный прямой SQL/QuerySet.update обходят модельные проверки.
Новых библиотек, изображений, внешних шрифтов и CDN не добавлено.
Основной агент принял этап после независимого review и повторного полного
набора65passed. Перед версионированием остановлен только QA-контейнер
`deanery-schedule-20261104`; Docker подтвердил его отсутствие. Контейнер
работал с --rm: его временные БД удалены вместе с ним. Другие контейнеры,
образы и volumes не затрагивались. Следующий шаг — commit/push принятого этапа.
