- Исходный main чистый, Q01/Q02 pushed `архивная-версия`,331tests. Читать TASK/AGENTS, ARCHITECTURE §§2/3/10/13/14, PLAN D02, STATE, docs/agents/WORKFLOW.md, существующие production configuration/foundation tests и docs/licenses.md.

## Законченный результат

Собрать Docker image приложения с runtime-only locked зависимостями и Compose-контур PostgreSQL17.11 + app/Gunicorn + Caddy HTTPS; проверить реальный путь через TLS, внутренние порты, proxy/CSRF/CSP/cookies, сохранение заявки после restart. Полный native/OS license/CVE аудит и release/rollback — отдельный следующий подэтап; не объявлять весь D02 или готовность к публикации завершёнными.

## Контракты образа и запуска

1. `deploy/Dockerfile`: multi-stage, официальный Python3.13 актуальный patch/uv; точные version+digest реально проверить registry/pull, не выдумывать. `uv sync --locked --no-dev --no-install-project`, не менять pyproject/uv.lock. Runtime без uv/compiler/tests/IDE/.git/.env/private/docs-evidence; только явные COPY app/config/manage/static плюс нужные лицензии. `.dockerignore` — allowlist context, не `COPY . .`. Сохранить installed `.dist-info/licenses` и `docs/third-party/libargon2-LICENSE.txt`; остальные upstream notices не вырезать. Build collectstatic отдельным минимальным `config/settings/build.py` без production credentials/БД/выключения manifest. Build setting не предназначен для запуска web.
2. App runtime uid/gid non-root, read-only rootfs и собственный tmpfs `/tmp`, cap_drop ALL/no-new-privileges, Gunicorn2workers×4threads, timeout/headers limits; graceful stop, безопасные логи без паролей/cookies/body/URL query/traceback. Миграции НЕ в worker entrypoint. Collectstatic в image; никаких runtime downloads/CDN. Health внутри app проверяет настоящее DB readiness, не считает redirect200 успехом. Health при HTTP loopback разрешить только для `/health/live/` и `/health/ready/` через точный SECURE_REDIRECT_EXEMPT; приватные URL остаются HTTPS-only.
3. `deploy/compose.production.yaml`, `deploy/Caddyfile`, `deploy/production.env.example` (заглушки), `deploy/postgres-init.sh`: БД без ports и с named data volume, app без ports, только Caddy80/443. Backend network internal (app/db), frontend internal (app/Caddy), Caddy отдельно edge с egress для будущего ACME. Production требуемый host/domain и HTTPS origins, никаких wildcard/DEBUG. Caddy config без публичного admin API и unsafe CSP; отделить read-only config от writable Caddy data/config volumes. Контейнеры не монтируют host project/env/SSH; Compose env_file берётся оператором только из приватного явного пути. Не читать пользовательскую .env.
4. App DB-role НЕ superuser/createdb/createrole. PostgreSQL bootstrap role отдельно, app role с правом own app schema для миграций, SCRAM/password (не trust для этого production rehearsal), no PUBLIC schema-create. Init script одноразовый для пустого собственного volume, env passwords не печатать. DB credentials обязательны, не defaults/secrets в Docker build args/layers. Отдельный явный one-shot `docker compose run --rm app python manage.py migrate --noinput`, после DB health, до web. Bootstrap demo через private env/getpass существующей команды, не baked в image. Повторный init не сбрасывает данные; отсутствующую роль на старом volume не обходить superuser приложением.

## HTTP/proxy/security

5. Caddy единственный peer, имеющий сетевой путь к app; Caddy форсирует `X-Forwarded-Proto` реальным `{scheme}` и `X-Real-IP` реальным `{remote_host}`, перезаписывает/удаляет клиентские XFF/Forwarded. Не доверять upstream/CDN: такого слоя нет. В production установить отдельный AXES_CLIENT_IP_CALLABLE `apps/accounts/proxy.py::client_ip`: брать один валидный X-Real-IP ТОЛЬКО если реальный REMOTE_ADDR входит в явно заданный `DJANGO_TRUSTED_PROXY_CIDRS`, иначе использовать валидный peer. Разобрать ipaddress, списки/мусор не доверять; reject wildcard `/0` config, required production config. В Compose frontend subnet и trusted CIDR одна явно согласованная переменная; использовать небольшой configurable private subnet, проверить отсутствие collision у своего QA. Local/test callable оставить прежним. Не менять REMOTE_ADDR глобально и не добавлять публичный debug endpoint.
6. Существующий SECURE_PROXY_SSL_HEADER сохраняется при условии изоляции app и forced Caddy XFP; не разрешать forwarded IP без peer validation. Документировать trust boundary и egress/private networks. HSTS пока0 до публичной проверки, не preload/includeSubDomains. Session cookie: Secure+HttpOnly+SameSite. CSRF cookie: Secure+SameSite, остаётся читаемым для UI marker из ADR001; HttpOnly для него не включать. CSRF, private no-store, роли/owner/Argon2 без ослаблений.
7. CSP Caddy: self для JS/CSS/img/fonts/connect, object-src none, frame-ancestors none, base-uri/form-action self; no inline/eval, без external CDN. Security headers nosniff/referrer/frame. Request body cap64KiB (инженерный), header/read/write/upstream timeouts; стабильные 413 и недоступный upstream, без traceback. Внешний HTTP перенаправляет на HTTPS даже с поддельным XFP. В QA TLS local CA `tls internal` отдельным overlay/config, без ACME/публичныхDNS и установки CA в host. Production конфиг не зависит от QA env и auto TLS нельзя молча заменить insecure HTTP.

## Проверки и безопасная QA-среда

8. `scripts/verify_production.py` — узкий воспроизводимый runner либо столь же воспроизводимая процедура с материалами (предпочтительно script): собственный unique project/resources+labels, создаёт секреты только в памяти/закрытой временной директории, build context из явного allowlist без secrets, docker nativeWindowsCLI может принимать tar на stdin (не host mounts и не реальный source dir через Windows-путь). Реально build/pull pinned images; QA Compose генерируется только для своего unique project с loopback high ports Caddy и private CA, не пользовательский dev5432/8000. Windows Docker daemon и WSL paths: use tar/cp собственного QA материала вместо bind mounts/чтения host config. Не принимать arbitrary existing URL/DSN/project/volume как input. Docker endpoint толькоlocal. Cleanup ownership-before-delete, exact created resources, проверка отсутствия; timeout-after-create должен оставаться tracked. Не broad prune. Если безопасный runner выходит слишком большим — согласовать меньшую owned rehearsal процедуру, не строить инфраструктурный framework.
9. Подтвердить Python/runtime versions, image nonroot, runtime dependency closure безpytest/playwright/ruff/uv, no secrets в context/image/history, healthcheck/порты/readonly. Реальный TLS CSRF login2студентов+оператор, schedule/grades, заявка→статус, чужойUUID404; Caddy security headers/manifest static200, браузер без CSP/script errors. Использовать local CA explicitly/контекст браузера для own QA без host trust changes; не выдавать ignore_https_errors за проверку public cert. Spoofed XFF/X-Real-IP не меняют реальный trusted IP в DB Axes counters; untrusted peer header не принимается unit tests. HTTP XFP spoof не обходит redirect, oversized POST413 без записи. Restart app/db с сохранённой заявкой, не удалять volume до проверки. Prod `manage.py check --deploy` с честным HSTS0 warning; readiness при остановленной БД не200 и восстанавливается. Минимальный smoke на360/1440 без новых screenshot history; полный app regression отдельной own suite PG и root review после freeze.
10. Новые `tests/test_production.py` по рискам proxy config/parser и build settings; `tests/test_foundation.py` только fixture production_env + проверки нового обязательного trusted CIDR, без ослабления прежних tests. Dependencies/schema не меняются. Existing fullsuite331+новые должен проходить. Не запускать fullsuite параллельно root. Сообщить writer freeze, точные retained QA ресурсы/команды для независимого root rerun; будущую native/OS audit часть отметить pending. Не повторять PNG.

## Владение

Разрешены: `.dockerignore`, `deploy/Dockerfile`, `deploy/compose.production.yaml`, `deploy/Caddyfile`, `deploy/production.env.example`, `deploy/postgres-init.sh`, необходимые узкие `deploy/` QA overlay/helper configs без секретов; `config/settings/build.py`, `config/settings/production.py` только оговорённые trusted CIDR/health/existing strictness, `apps/accounts/proxy.py`, `tests/test_production.py`, оговорённая fixture `tests/test_foundation.py`, `scripts/verify_production.py` и узкий companion QA helper при необходимости; `docs/operations/production.md`, README только production runbook link; `docs/evidence/D02-01/implementation.md` и безопасные metadata результатов. Вне allowlist сначала root.

Root владеет prompt/architecture/decisions/review/STATE/PLAN/licenses и прежним versioning. Секреты, raw env/config, private CA keys, cookies, dumps/SQL, персональные значения не в evidence. Только counts/status/version/digest/technical aggregate. Не выводить compose config с подставленными паролями. Не читать SSH/private `.env`, не менять dev/OS permissions. Git commit/push только после root accepted + отдельного allowlist, main/origin с атрибуция команды.

Уточнения root после предварительного чтения: tiny derived config images разрешены как `deploy/Dockerfile.caddy` и `deploy/Dockerfile.postgres`; они не содержат секретов. Production runtime environment задаётся явными per-service maps: bootstrap DB password не попадает в app/Caddy, приложение знает только собственную ограниченную DB-role. Общий `env_file` со всеми секретами для каждого сервиса запрещён. QA работает с явно своей конфигурацией без автоматического чтения пользовательской `.env`. Production browser smoke дополнительно проверяет смену аккаунта в двух вкладках, чтобы cookie/security конфигурация сохраняла ADR001. Не использовать плавающий Dockerfile syntax frontend. Build context исключает скрытые env/key файлы также внутри app/config.
