## Замечания и решения

1. Root обнаружил по исходному коду, что home/profile принимали POST и возвращали read-only HTML. Это несоответствие HTTP-контракту, не установленная утечка или изменение данных. Root разрешил только `@require_GET` и соответствующие imports в двух views. Текущие authenticated POST405 и guest-valid-CSRF POST302 независимо подтверждены полным прогоном; старое поведение не выдаётся за отдельно выполненный pre-fix HTTP-тест.
2. Root потребовал проверку гостя с настоящим CSRF token наряду с авторизационным клиентом без enforce_csrf. Исполнитель добавил 7 случаев; они вошли в независимый suite. Ожидаемые 302 и403 не смешиваются.
3. Первая матрица исполнителя ошибочно ожидала комментарий заявки в списке. Уточнён тест: список проверяет точный count, карточка — персональный marker. Приложение не менялось ради неверного ожидания. Сохранена подробная прежняя проверка фильтров/пагинации/XSS.
4. Root уточнил архитектурную таблицу по существующему URLconf: Announcement использует int, добавлены ранее не перечисленные notification open и deadline detail. Данные, идентификаторы и маршруты приложения этим не менялись.

Обязательных незакрытых замечаний к принятому результату нет. Новые тесты не заменяют прежние проверки опубликованных оценок, фильтров, деактивации, отзыва scope, квоты, напоминаний, расписания и seed: все они выполнены в полном suite. Отдельно повторять уже прошедшие races без нового изменения не потребовалось.

## Границы и следующий шаг

Q01/Q02 приняты для реализованного локального baseline. Матрица не объявляется доказательством для ещё не созданного API/partials/экспорта: такие изменения потребуют новых негативных проверок. Не обещается сериализация административного отзыва role/scope одновременно с уже исполняющейся транзакцией; такой протокол/интерфейс не входит в baseline. Неизменность истории обеспечивается текущим ORM API/ограничениями, это не защита от администратора БД.

Потеря ответа после реального commit уже проверена Q04 на трёх движках, restart/restore — Q05. Эти результаты не означают проверку отключения диска во время транзакции или production disaster recovery. Один существующий warning относится к pytest-playwright и будущему pytest10, текущий pytest ограничен `<10`.

Удалённый CI, production HTTPS/proxy/CSP/native licenses, аппаратный телефон/BFCache, V2, доступность из РФ и публикация остаются отдельными работами. Следующий независимый блок — локальная подготовка D02; публикация по-прежнему требует V2 и решения по хостингу.

## Cleanup и версионирование

Собственный QA PostgreSQL удаляется после root regression только после exact inspect ID/owner/image/port/tmpfs; отчёт — [cleanup.md](cleanup.md). Пользовательский dev не используется и не удаляется.

После проверки документов root передаёт точный allowlist исполнителю. Только обычный commit/push в `main`/`origin`, обязательный trailer `атрибуция команды`, без force/amend или обхода hook. Staged diff/check и фактическое совпадение HEAD с `git ls-remote origin refs/heads/main` обязательны; до сверки Git статус не называется pushed. Результат — [versioning.md](versioning.md), собственный SHA фиксируется в финальном отчёте без изменения уже созданного коммита.
