# REQ01 · Приёмка кнопки принятия заявки

**Статус** — `accepted`. 20 ноября 2026 года. CORE-04, PRD-02, PRD-04, TECH-03. [Постановка](prompt.md) · [Реализация](implementation.md)

В новой заявке оператор видит кнопку «Принять в работу». Проверено, что открытие карточки не отправляет POST. Кнопка отправляет прежний защищённый переход с актуальной версией. После клика отображается статус «В работе» и доступна форма завершения или отказа. Повтор из устаревшей вкладки возвращает 409, после обновления карточки дальнейшее действие сохраняется.

- PostgreSQL 17 в отдельном тестовом контейнере — 180 серверных сценариев для заявок и изоляции доступа.
- Chrome и тот же тестовый PostgreSQL — 15 сценариев на ширинах 360–1440 px. Включены путь заявки от подачи до готовности, уведомления, отказ, фильтры и конфликт версий. Девять сценариев вне выборки. Pytest выдал предупреждение об устаревающем способе задания фикстуры `base_url`.
- Ruff lint и format для пяти файлов тестов, `git diff --check` прошли.

Рабочая локальная БД проверена в транзакции только для чтения. Ранее созданная для ручной проверки заявка уже была в статусе «Отклонена». Ожидающих принятия заявок в очереди оператора не было. После перезапуска воркера Gunicorn локальный `/health/ready/` ответил HTTP 200. Смена статуса проверена в изолированной базе.
