Исполнитель: gpt-6.1-sol / low по явному вызову родителя. Прочитаны TASK.md, AGENTS.md, ARCHITECTURE §§6–8, PLAN, постановка MSG01 и актуальный taste-skill 2.5.1. Применены существующая палитра, карточка, типографика, формы и мобильные правила. Новые библиотеки, графика, JS и внешние ресурсы не добавлены.

Добавлен partial `_conversation.html` после деталей обращения. Роли автора показаны как «Студент»/«Деканат», текущий пользователь обозначен «Вы»; логины не показываются. Текст выводится стандартным autoescape Django, переносы сохраняет CSS. Сообщения newest-first Page выводятся reversed. Навигация различает более ранние и более новые страницы. Пустое состояние объясняет назначение переписки.

Форма использует CSRF, hidden fields `message_form`, отдельный endpoint для роли, явный label «Сообщение», видимые ошибки с alert и стандартным Django id errorlist. Сохраняется bound body. Родителю передана необходимость связать подсказку `id_body_helptext` в backend форме; связь ошибки обеспечивает Django 5.2. История статусов и действия заявки сохранены.

Расширен существующий browser roundtrip на 360/1440: студент отправляет многострочный текст с HTML-тегами как текстом, оператор читает и отвечает, статус проходит submitted → in_progress → ready, студент после повторного входа видит оба сообщения, другой студент получает 404. Есть проверки отсутствия overflow, подписи роли, отсутствия em markup. При UPDATE_EVIDENCE=1 сохраняются screenshots MSG01.

Фактические проверки: `python3 -m py_compile tests/test_requests_browser.py` успешно; `.venv/bin/ruff check tests/test_requests_browser.py` успешно; `.venv/bin/ruff format` применён; `git diff --check` успешно. Первоначально ruff указал одну длинную строку; исправлено formatter. Browser запуск, collectstatic и визуальная проверка переданы родителю по постановке, не объявлены пройденными.
