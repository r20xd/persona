# U01 — карта экранов

Документ задаёт структуру работающего кабинета; цвета/компоненты описаны в design-system.md. U04 обновляет навигацию и фильтры по указанию пользователя.

## Навигация

Студент: «Главная», «Расписание», «Успеваемость», «Заявки», «Дедлайны», «Уведомления». Профиль — кнопка с именем в шапке, выход — POST-действие. На телефоне основные разделы в нижней панели с подписями, на desktop — сбоку. Оператор получает отдельно очередь, уведомления и выход.

| Экран | Основное содержимое | Главное действие / дальнейший путь |
| --- | --- | --- |
| Вход | Название концепта, логин/пароль, объяснение демо | Войти; никаких настоящих учётных данных вуза |
| Главная | Ближайшее занятие или экзамен, «Требует внимания» во всю ширину, изменения расписания | «Заказать справку», открыть расписание или событие в радаре |
| Профиль | ФИО, факультет, направление, курс, группа | Вернуться в кабинет; редактирования нет |
| Расписание | Сегодня/неделя/сессия, даты, карточки занятий и экзаменов | Сменить вид, открыть изменение |
| Успеваемость | Семестр, дисциплины и опубликованные результаты | Переключить семестр |
| Сессия (в Расписании) | Экзамены/зачёты с местом/временем, отмены | Выбрать семестр или день/неделю занятий |
| Заявки | Список своих заявок со статусами и датами | Создать или открыть заявку |
| Новая справка | Вид, назначение, необязательное пояснение, предупреждение о fiction | Отправить; при ошибке исправить поля |
| Карточка заявки | Номер, тип, актуальный статус, история и публичный ответ | Отменить только отправленную заявку; вернуться к списку |
| Дедлайны | Личные задачи с датой, списки в работе и выполненных | Добавить задачу, отметить выполнение или вернуть в работу |
| Уведомления | Объявления и личные события с датой, unread | Открыть связанный объект, отметить прочтение |
| Очередь оператора | Разрешённые заявки, фильтр статуса, пагинация | Открыть карточку |
| Карточка оператора | Сведения заявки, история, допустимые переходы | Взять в работу/завершить/отклонить с причиной |

## Мобильная компоновка

При 360 px — одна колонка, занятия сгруппированы по дням, результаты по дисциплинам. Не использовать горизонтальный календарь на семь узких колонок. У нижней панели учесть safe-area; контент и submit не перекрываются. На desktop допустимы несколько колонок сводки, но порядок чтения остаётся логичным.

## Состояния и доступность

- Серверные страницы сразу содержат данные; индикатор ожидания показывается только при реальном запросе.
- У пустого списка есть объяснение и уместное действие: следующая неделя, новая заявка, возврат в раздел.
- Форма сохраняет введённый текст при валидационной ошибке, фокус переводится на сводку ошибок; сетевой сбой восстанавливает кнопку.
- Статусы различаются текстом, не только цветом. Видимый focus, labels, клавиатурное управление и читаемость при zoom обязательны.
- Истечение сессии открывает полноценный вход; 403/404/500 не раскрывают личные данные.
- Одна компактная отметка «Конкурсный концепт · Неофициальный сервис» доступна на входе и в оболочке кабинета.

## Что показать на V1

Работающую оболочку, вход и пример страницы со сводкой на вымышленных данных в ширинах 360 px и desktop. Демонстрационные статические данные до подключения backend явно обозначить. Дать адрес/инструкцию и попросить оценить читаемость, расположение разделов и общий стиль. Не выдавать этот предварительный показ за реализованное ядро.
