# MSG01-A · Backend и проверки

Исполнитель: gpt-6.1-sol / low, параметры переданы родителем явно. Инструменты: Python/Django ORM и migrations, pytest, Ruff; существующий локальный .venv. Файлы backend, новая миграция 0002_request_messages и tests/test_request_messages.py; старый migration-test requests обновлён для восстановления актуальных leaf migrations.

Реализованы сообщения заявки с лимитом 2000, DB-проверками непустого текста/длины и уникальным ключом заявки/автора/отправки. POST обеих ролей проверяет область заявки, свежую активную роль и блокирует account/application, а оператор также текущую запись scope до commit. Повтор одинакового нормализованного текста возвращает существующее сообщение, конфликт текста — 409. Сообщения не изменяют статус/версию/историю. Уведомления без содержания сообщения создаются в той же транзакции только активным адресатам требуемой роли/группы. Деталь содержит отдельную страницу 20 сообщений с author select_related, новую форму и строгую валидацию messages_page. CSRF и no-store штатные.

Проверки: `.venv/bin/ruff check apps/requests tests/test_requests.py tests/test_request_messages.py` — passed. Изолированный PostgreSQL 17 предоставлен родителем. `.venv/bin/pytest tests/test_requests.py tests/test_request_messages.py -q` — **43 passed in 5.90s**. Покрыты повтор/retry и concurrent changed payload, межстуденческий доступ/оператор без scope, stale role/active, ограничения БД, аудитория и rollback уведомлений, PRG, CSRF обеих ролей, сохранение при повторном входе, escaping HTML, границы пагинации, миграционная сохранность существующих заявок и прежние сценарии заявок.

Первый запуск: 40 passed / 1 failed. Причина: прежний тест снятия requests миграций восстанавливал только 0001, после чего threaded message test не находил новую таблицу. Исправление — восстановление актуальных leaf migrations в finally. Повторный полный прогон указан выше.

Ограничения: браузерную и независимую приёмку выполняет родитель. Рабочая БД, публикация и Git не изменялись. uv не смог создать cache lock в sandbox; команды запускались через уже установленный .venv, без установки зависимостей.

## Исправление независимого ревью

Родитель указал риск deadlock встречных отправок: эксклюзивная блокировка user мешала FK KEY SHARE уведомления другому отправителю, ожидающему заявку. Actor теперь блокируется PostgreSQL `FOR NO KEY UPDATE` (`no_key=True`): обновление роли/активности по-прежнему ждёт commit, а проверка внешнего ключа уведомления проходит. Блокировки заявки и scope сохранены. Добавлен concurrent student/operator regression, проверяющий две записи, двух адресатов и неизменность статуса/версии/events. Paginator не присоединяет author (UI использует author_id), detail выбирает student одним запросом. Повторный Ruff passed; полный server прогон — 44 passed in 6.15s.
