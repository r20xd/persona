# Q03: локальная проверка безопасности сессий

Связь: SEC-01/02, PRD-05, CORE-01/04, TECH-03/06. Это локальный аудит ограниченного объёма, не подтверждение production HTTPS/CSP или полной готовности Q04.

## Найденные дефекты и изменения

Реальный Chromium воспроизвёл устаревшую форму: студент A набирает заявку, во второй вкладке выходит и входит B, возврат в первую сохраняет форму A. Прежний history.js проверял только `pageshow.persisted`. Теперь общий скрипт страниц проверяет смену cookie CSRF при focus, возвращении видимости и pageshow. Django уже меняет CSRF при login; logout теперь также вызывает штатный rotate_token. BroadcastChannel передаёт только сигнал проверки; отказ его конструктора не ломает fallback. Смена маркера синхронно удаляет приватный DOM, выводит нейтральное состояние с ссылкой повтора и делает GET через location.replace. При смене аккаунта открывается главная; восстановленный POST-документ также направляется на главную, чтобы не повторить POST. При pageshow.persisted с прежним маркером GET-документ запрашивается по своему URL. Неизменённый маркер сохраняет форму. Нет polling, storage, нового endpoint или передачи ключа сессии в JS.

Cookie CSRF служит только сигналом обновления UI. Авторизацию и владение проверяет сервер. Старый hidden CSRF после смены аккаунта отклоняется сервером с403; JS для этого не требуется. Истечение сессии и деактивация обнаруживаются следующим серверным запросом; мгновенное отслеживание offline не заявляется.

`provision_accounts` теперь показывает штатные причины ValidationError Django, не введённый пароль, и не маскирует неожиданные исключения. Проверены длина, числовой/распространённый/похожий пароль и rollback всей операции при ошибке второго аккаунта. Повторное provisioning не меняет существующие пароли (ранее существующий regression).

## Проверки и границы

Новые сценарии: `tests/test_session_security.py`, `tests/test_session_security_browser.py`. Браузер использует собственную временную БД, статический каталог, динамический loopback port и DEBUG=False Gunicorn/WhiteNoise; секреты генерируются и не сохраняются в отчёте. Cleanup охватывает ошибки setup. PostgreSQL17.11 и Chromium156.0.8078.4.

| Риск | Фактическая проверка |
| --- | --- |
| Смена A→B, A→guest в общем context | Реальные страницы и cookie; старый текст удалён, сервер после перехода показывает текущего студента |
| Обычный возврат, отдельные contexts | Незавершённый текст сохраняется; выход одного context не завершает другой |
| Недоступный BroadcastChannel | Конструктор бросает SecurityError, явное focus событие использует fallback без pageerror |
| Logout/history | DB session удалена, старый cookie и прямой URL дают login; Back/Forward не показывают профиль |
| BFCache | Реальные переходы дали `pageshow.persisted=0` из7 событий; попадание в BFCache не подтверждено. Отдельный synthetic persisted handler проверяет удаление DOM до aborted reload и обычную ссылку повтора |
| Истечение/deactivation | Старая форма с выключенным JS приводит к входу; число заявок не меняется |
| XSS | Комментарий заявки и объявление отображаются текстом в браузере, img/script не создаются/не исполняются |
| Устаревший POST-документ | Реальная ошибка валидации POST, затем A→B: только GET навигации, без dialog/повторной заявки/старой формы |
| Серверный CSRF | Старый токен после A→B даёт403 без новой заявки; ошибка предлагает открыть кабинет или вход |
| Session/cookie | Login меняет session key; logout меняет CSRF marker; session cookie HttpOnly/SameSite=Lax; private no-store |
| Существующее покрытие | Access matrix, external next, Axes, CSRF logout, safe503/logs, production flags и fail-closed configuration остаются в accounts/foundation suites |

Production Secure cookies/HTTPS redirect проверяются synthetic settings и существующими regression tests. Caddy, proxy IP, CSP enforcement, публичный HTTPS/HSTS, доступность из России, Firefox/WebKit и реальный телефон остаются проверками D02/Q04; локальный Chromium их не подтверждает.
