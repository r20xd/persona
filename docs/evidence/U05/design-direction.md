# U05 — решение по фактическому аудиту и направление редизайна

Root принял фазу A: новые live BEFORE PNG, реальные Taste consistency home55FAIL/34WARN и login21FAIL/10WARN, perf homePASS на360/1440. Сырые результаты остаются в evidence, не заменяются интерпретацией. Большинство FAIL касается landing rules (hero/section tiles/photographs) или snapshot-only link checks. Они не являются требованиями личного кабинета. Полный marketing GATE:PASS не заявляется. Подтверждённые приложением замечания и конкретные решения ниже.

## Образ продукта

Спокойное профессиональное учебное рабочее пространство. Палитра U04 сохраняется: near-black navy121524, steel384C65/485F88, light9DACCC/C0C9DB, белые поверхности. Системный sans-serif, без внешних fonts/фото/зависимостей. Крупная типографика для основных событий, точные подписи для данных; нейтральный интерфейс и один основной акцент. Это существенный редизайн композиции/компонентов, а не ещё одна замена оттенков.

## 1. Общая оболочка и навигация

- Исправить реальное расхождение header/main content edges. Единая ширина контента и gutters для шапки, заголовков, панелей и форм. Умеренная sidebar224–232px, компактная шапка72–80px, единая spacing scale4/8/12/16/24/32/48.
- Desktop brand перенести в верх sidebar; общий header со спокойным названием раздела/ссылкой профиля/выходом. Mobile brand остаётся в шапке, пять основных разделов в bottom nav. Оператор получает согласованный shell своих двух разделов без студенческих маршрутов. Дубли header markup можно выделить в partials.
- Unicode разностильные значки заменить едиными собственными SVG из campus.svg (добавить собственные простые paths при необходимости). Тексты/aria-current, названия «Успеваемость» и сессия в «Расписании» сохранить. Длинная mobile подпись читается/не пересекается с соседями.
- Нативную серую кнопку «Выйти» и прочие secondary controls привести к общей семейству: одинаковые высоты44–48px, радиусы8–12px, primary/secondary/text-action. Focus мгновенный/контрастный, включая brand на тёмном login. Scroll-behavior:auto убирает задержку при Tab; hover/press деликатный, reduced-motion соблюдён.
- Одна compact concept notice в общей оболочке, без отдельной большой рамки/панели. Исходные поля/права/CSRF/no-store/history safeguards не менять.

## 2. Главная — иерархия вместо равных коробок

- Ближайшее реальное событие должно быть в первом экране (в том числе mobile), а не после высокого radar. Выразительная компактная панель с дисциплиной, датой/временем, аудиторией/преподавателем и рабочей ссылкой. Не выдумывать «сейчас»/«сегодня», когда событие в будущем.
- Затем важные действия: radar со счётчиком реальных причин и компактными строками/карточками, ясно видимыми действиями. До6 существующих событий/честный total сохраняются, без скрытого удаления источников. Дополнительные read-only детали можно раскрывать, но важное видно сразу.
- Digest должен оставаться рабочим и видимым: все identities, которые включены в кнопку «Отметить показанное», действительно отрисованы и не спрятаны за закрытым accordion. Empty state короткий, не занимает треть экрана.
- Вторичные сведения оформить плотнее: counts успеваемости, дедлайны, заявки, объявления. Различать primary workspace и supporting summaries; уменьшить пустые разрывы неравных grid rows. Не дублировать развёрнутый перенос трижды. Последние изменения можно оставить компактным read-only disclosure/списком; полный source доступен по ссылке расписания. Непрочитанные сообщения/объявления и их прямые переходы не терять.
- Не придумывать charts/progress/учебные прогнозы. Только существующие опубликованные результаты/точные counts/реальные сроки. K01 не трактует отсутствие результата как задолженность.

## 3. Остальные экраны

- Расписание/сессия: ясные tabs/toolbar/выбор даты или семестра, структурированный timeline/компактные строки занятий, различимые отмены и изменения. Дата/время имеют приоритет, адрес/преподаватель вторичны, история раскрывается обычным details.
- Успеваемость: аккуратная summary strip и читаемые course/work rows; исключить избыточные большие вложенные карточки. Баллы0/неопубликованное/зачёты сохраняют прежнее значение. Если используются progress-элементы, только по известным points/max, без выдуманных агрегатов.
- Заявки/оператор: согласованный filter toolbar, компактные записи с названием/назначением/датой/статусом; UUID вторичен и не доминирует, полный идентификатор доступен. Новая заявка/карточка/история/transition buttons читаются, POST остаётся явным.
- Уведомления: события/объявления/сроки визуально разделены, непрочитанное различается текстом/малым акцентом, без тройного повторения одинаковых пояснений. AutoGET+Back+JSoff сохранены.
- Профиль: собранная identity panel и структурированный dl, полезные рабочие ссылки.
- Login: собственная композиция с конкретным заголовком о кабинете, понятной формой, иконками трёх реальных разделов/типографическим мотивом бренда. Уменьшить пустую левую половину, форму и action держать видимыми на360. Не показывать анонимному чужие данные даже в качестве украшения; не добавлять фиктивные отзывы/числа/фальшивые кнопки. 3D/stockart не нужны.

## 4. Реализация и приёмка

Можно отделить actual app stylesheet от большого legacy preview.css: новая общая workspace.css/partials плюс чистые component CSS, не сотни конфликтующих late overrides. Preview — архив прежней визуальной версии, не должен изображать новые backend функции. Существующие реальный app UI/навигация/функции должны получить единую систему.

Фаза B разрешена: только разрешённые prompt UI files/новые собственные SVG и design tests. Models/selectors/services/views/URLs/schema/lock/infra не менять без причины/решения root. Никаких дополнительных SQL запросов из shared header ради имени/счётчиков — использовать доступный контекст, роль и существующие ссылки. Business copy сохранять, если не мешает ясности; старые тестовые проверки не удалять ради дизайна.

До/после повторить одни и те же Taste flags/seeded data/sanitizer. Требования snapshot-only/marketing оценить отдельно, реальные keyboard/contrast/overflow/tap-size проблемы исправить. Quick skips и perf CPU/static-render limits указать. Реальный authenticated браузер проходит прежний путь, новые keyboard Tab stops видны сразу и после settle; header/main alignment измеряется относительно content area после sidebar. Root оценит визуальную разницу по новым360/1440 и tablet PNG, затем один independent fullsuite после code freeze. Публикации нет.
