# Обновление и восстановление persōna

Инструкция для оператора после согласования первого размещения. Она рассчитана на существующую конфигурацию [production Compose](production.md). Откройте окно обслуживания и предупредите пользователей о паузе. Запишите текущий Git SHA и ссылки на образы приложения и Caddy. Подготовьте проверенные образы новой версии. Обновление самого PostgreSQL требует отдельной процедуры.

## 1. Остановить запись и снять копию

В shell на сервере задайте путь к закрытому файлу конфигурации, имя действующей БД из этого файла и путь к каталогу резервных копий вне репозитория. Подставьте свои значения в примерах. Входные параметры берутся из указанного файла Compose.

```sh
export COMPOSE_DISABLE_ENV_FILE=1
release_config=/absolute/private/path/production.env
release_db=deanery
backup_dir=/absolute/private/path/backups
dc() { docker compose --env-file "$release_config" -f deploy/compose.production.yaml "$@"; }
```

Сохраните прежнюю конфигурацию с ограниченным доступом. Остановите приложение и убедитесь, что отдельные процессы записи в БД завершились. PostgreSQL оставьте запущенным.

```sh
dc stop app
umask 077
mkdir -p "$backup_dir"
backup=$(mktemp "$backup_dir/deanery.XXXXXXXX")
if dc exec -T db sh -ec 'exec pg_dump -U "$POSTGRES_USER" -Fc -d "$1"' sh "$release_db" > "$backup" &&
  test -s "$backup" &&
  dc exec -T db pg_restore --list < "$backup" > /dev/null; then
  printf 'Копия создана: %s\n' "$backup"
else
  printf 'Копия не подтверждена. Остановите обновление.\n' >&2
fi
```

Продолжайте после успешного завершения всех трёх проверок. Сохраните путь к архиву и время снятия копии. Список объектов проверяет заголовок и каталог архива. Пригодность для восстановления подтверждает отдельное восстановление. В архиве есть данные сессий и хеши паролей. Храните файл в закрытом каталоге с доступом только оператору. [Документация PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgrestore.html).

## 2. Применить обновление

1. Укажите новые ссылки на образы в приватной конфигурации. Проверьте список миграций командой `dc run --rm --no-deps -T app python manage.py migrate --plan`. Примените их один раз командой `dc run --rm --no-deps -T app python manage.py migrate --noinput`. При ошибке оставьте сайт в окне обслуживания и оцените состояние схемы и данных.
2. После успеха поднимите новую версию командой `dc up -d --no-deps app caddy`. Для обновления прокси выберите образ Caddy, собранный с актуальным `deploy/Caddyfile`.
3. Получите HTTP 200 на `https://<домен>/health/ready/`. Затем выполните короткую проверку на вымышленных аккаунтах: вход, расписание или оценки, создание заявки, смена статуса оператором, отображение нового статуса студенту. Второй студент должен получить отказ при открытии той же заявки. Запишите фактический SHA и результат проверки до объявления об окончании обслуживания. [Docker Compose](https://docs.docker.com/reference/cli/docker/compose/run/).

## 3. Восстановить работоспособность

Если прежнее приложение совместимо с текущей схемой, верните его образ и проверьте сценарий из шага 2 на текущей БД. При несовместимости сохраните текущую БД для разбора и подготовьте отдельную пустую БД с новым именем. Перед переключением оцените, какие изменения после снятия копии придётся перенести.

```sh
restore_db=deanery_restore_release
dc stop app
dc exec -T db sh -ec 'exec createdb -U "$POSTGRES_USER" -O "$DB_USER" "$1"' sh "$restore_db"
```

Продолжайте только после успешного создания новой БД. Восстановите доверенный архив транзакционно от роли приложения.

```sh
dc exec -T db sh -ec 'exec pg_restore -U "$DB_USER" --single-transaction -d "$1"' sh "$restore_db" < "$backup"
```

Выберите версию приложения, совместимую с восстановленной схемой. После успешного восстановления укажите новое имя в `DB_NAME` приватной конфигурации и запустите приложение по шагу 2. При переходе на новую версию сначала примените необходимые миграции к восстановленной БД. Выполните проверку шага 2 до возобновления работы. Сохраните исходную БД и релизную копию. [Документация PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgrestore.html).
