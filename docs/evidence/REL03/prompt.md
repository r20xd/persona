# REL03 · Демо к дате показа

Реализовать REV-05 из аудита `docs/evidence/REV01/audit-and-plan.md` для CORE-02, CORE-03, CORE-05, DATA-01, DEMO-01 и TECH-03. Источники — TASK.md, AGENTS.md, ARCHITECTURE.md §12. `seed_demo` и все существующие пользовательские данные сохраняют текущие контракты.

Добавить management-команду `prepare_demo_window [--anchor-date YYYY-MM-DD]` в apps/academics. Она работает поверх выполненного `seed_demo`, использует общий `demo_lock` и `transaction.atomic`. Дата по умолчанию — текущий день Москвы. Для нового окна допустимы сегодня и будущая дата. Команда не печатает персональные поля, пароли или конфигурацию. В одной транзакции проверить две активные вымышленные роли/группы, затем вызвать `extend_demo_schedule` для горизонта существующего семестра и добавить только недостающие события показа. Стабильные идентификаторы привязать к дате показа. Повтор не меняет уже созданные записи. Коллизия другого владельца приводит к отказу всей транзакции.

У первого студента добавить заметный перенос отдельного вымышленного занятия через `create_lesson` и `change_lesson`, с аудиториями и преподавателем. Исходное время `anchor + 4 дня`, новое `anchor + 8 дней`, время в Москве, отдельное от обычного слота. Это позволяет увидеть изменение в радаре и расписании на относительных днях 0, 3, 7. Для каждого студента добавить адресное объявление с действием/местом и отдельный новый срок к `anchor + 10 дней` через `create_deadline`, видимые в дни 0, 3 и 7. В учебных итогах сохранить все существующие оценки, в том числе ожидающие публикации. Добавить демонстрационный зачёт только если нет видимого зачёта и есть ещё пустая оценка в своём уже существующем курсе зачёта. Использовать `record_result` после блокировки CourseOffering и проверки отсутствия результата. Сессию оставлять с подписанными датами, при отсутствии подходящего актуального события в периоде добавить для каждого ближайший экзамен через `create_exam_event`, после блокировки offering, с уникальной попыткой и стабильной датой для этого окна. Требование к экзамену — он остаётся предстоящим в дни 0, 3, 7. Существующие ExamEvent, GradeResult, Lesson и их версии не обновлять, кроме самого нового урока в той же транзакции. Нет миграций, фейкового времени для HTTP и новых зависимостей.

Разрешены `apps/academics/management/commands/prepare_demo_window.py`, `tests/test_demo_window.py`, `docs/evidence/REL03/implementation.md`. Если нужен иной файл, согласовать до изменений. Основной агент изменяет архитектуру/README, принимает результат и ведёт Git. Соседняя REL04 меняет только пустое состояние расписания.

Проверки на PostgreSQL. Новый тест покрывает подготовку уже старого seed, наличие ближайших собственных занятий обоих студентов на 0/3/7, перенос первого, оценки и зачёт, будущий экзамен, видимый срок и только своё адресное объявление. Второй запуск проверяет идемпотентность и сохранение старых записей, заявок и прочтения. Проверить отказ на несовпадающих идентификаторах при необходимости. Фиксировать фактические результаты, не использовать рабочую БД и приватный .env. Не коммитить, не запускать субагентов.
