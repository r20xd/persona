# K01 — независимое ревью

- Ревьюер: основной агент gpt-6.1-sol/high. Исполнитель: gpt-6.1-sol/low, отдельный контекст, без дальнейшей делегации.
- Постановка: prompt.md; продуктовый контракт: ../../ux/attention-and-digest.md; отчёт: implementation.md.
- Требования: PRD-01–PRD-05, CORE-02–CORE-05, TECH-03/06, SEC-01. Дополнительные функции явно выбраны пользователем, не объявляются требованиями конкурса.
- Статус: **accepted** локально. Версионирование: pending, отдельный Git follow-up. Исходный HEADархивная-версия.

## Проверенный результат

Прочитаны фактические модели/миграция, выборки радара/сводки, сервис подтверждения, login hook, HTTP handlers, шаблоны/CSS и13 новых серверных/2 браузерных случая. Schema соседних приложений, зависимости, секреты, статика сторонних поставщиков и production infrastructure не менялись. Новые таблицы хранят только личное начало отслеживания и точные отметки событий; копии учебных данных не создаются.

Радар выводит опубликованные отрицательные итоги, сроки ±7дней, актуальные версии переносов/отмен и личные ready/rejected заявки. Есть причины, текстовые приоритеты и действия, максимум6 карточек и общий счётчик. Отсутствие оценки/сведений о сдаче не называется задолженностью. Сводка показывает до3 новых публикаций/событий каждой категории с честным счётчиком и остатком. Подписанный token ограничен9 показанными identities, user/state и30минутами; POST повторно проверяет текущие источники и роль/активность. GET не пишет; mark не сбрасывает уведомления или радар. Устаревшая публикация/вкладка не списывает новое, глобальный watermark не двигается.

## Исправления по ревью

Устранены fresh-user deletion/role ошибки, изменение прежнего login потока при отсутствующем профиле, отсутствие фактических old→new значений/конкретного действия в радаре и неоднозначность срока без связанной работы. Исторический переход заявки больше не зависит от текущей роли его автора. Счётчики согласованы с фактически отрисованными preview, пустые категории скрыты. В финальном UI нет обещания «остальных» при1из1 и дублирования одинаковых аудиторий/преподавателей при одной отмене занятия. Первоначальная ошибка sandbox подключения и вывод временного QA пароля в подробном traceback честно отражены исполнителем; это одноразовый credential удалённой QA DB, не пользовательский/service secret, в Git/evidence его нет. Родительские прогоны захватывали вывод и редактировали этот credential до публикации результата.

## Границы

Сводка начинает отслеживание с первого обычного входа после установки функции (либо явного POST для старой сессии). Предыдущая история не изображается непросмотренной. Просмотр сохраняется до явной отметки показанного, а не очищается автоматически при login/refresh. Новая версия оценки — публикация с новым published_at; редактирование старой оценки без повторного опубликования не создаёт новый пункт. События до начала отслеживания исключены по дате создания/публикации.

Новые browser cases проверены в Chromium; физический телефон и новые отдельные Firefox/WebKit прогоны не выполнялись. Публичного размещения/доступности из РФ/конкурсной сдачи нет. Остаточные D02 CVE не исчезают из-за K01: перед публичным релизом нужен актуальный аудит выпускаемого artifact. Отдельную сложную автоматизацию D03/D04 не выполняем по обсуждению с пользователем. Запуск/просмотр — VIEW.md; перед запуском новой версии необходим migrate.
